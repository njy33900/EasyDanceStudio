# EasyDanceStudio 고도화 명세 초안

- 문서 버전: 0.2 (2026-11-19)
- 상태: 구현 전 검토 초안
- 기준 코드: `v0.6` (`015177a`), Unity 6000.3.28f1 / URP 17.3.0 / Windows x64
- 상위 요구: `MMD_Studio_Spec_v1.1_Codex.md`의 1차 완료 기준 및 2차 `GFX-201`~`GFX-210`

## 1. 목적과 현재 기준선

목표는 외부 PMX/VMD를 불러와 재생하는 현재 앱을 **장면을 안전하게 만들고, 꾸미고, 결과물을 내보낼 수 있는 데스크톱 도구**로 발전시키는 것이다. 첫 번째 화면 목표는 **앱 창 전체를 3D 뷰포트로 쓰고 조작 UI를 필요할 때만 보이게 하는 것**이다. 이 문서는 기존 1·2·3차 구분을 대체하지 않는다. 1차 출시 준비에서 확인할 사항과 2차 기능에 들어가기 전 필요한 품질 작업을 함께 규정한다.

현재 구현: 다중 캐릭터와 정적 PMX 배경, 공통 재생 시계, 선택·변형 기즈모, 카메라/방향광/기본 후처리, `.mmdscene` 저장·복원. Debug/Release × Mono/IL2CPP에서 UI 95개와 별도 프로세스 복원 9개가 보고됐다. Codex는 `v0.6`의 Debug/Mono PowerShell 전체 빌드 및 95+9 검사, 최신 바이너리의 씬 26·복구 13·변형 21·물리 lifecycle 20 검사를 다시 통과시켰다. 이 수치는 **자동 검사 범위의 결과**이며 실제 마우스 조작, 다양한 외부 파일, 다른 PC의 품질 보증은 아니다.

유지할 제약: 일반 화면 물리 OFF(ADR-014), 테스트 에셋은 `Assets/`·Git·배포물 밖, 로컬 모델/Ollama 사용 금지. 드래그 앤 드롭은 1차 범위에서 제외한 결정(ADR-015)을 유지한다. 영상 출력은 Unity Editor 전용 Recorder에 의존하지 않는 Windows Player 기능이어야 한다.

## 2. 사용자 작업 흐름

1. 사용자는 앱 창 전체에 펼쳐진 장면을 보면서 조작 창·탭·아이콘을 숨기거나 다시 연다. UI를 모두 숨긴 상태에서도 뷰포트를 조작하고 UI를 복원할 수 있다.
2. 사용자는 PMX 캐릭터 2개 이상과 PMX 배경을 추가하고 각 캐릭터에 VMD를 연결한다.
3. 사용자는 카메라, 조명, 재질 스타일과 효과를 조절하고 재생 위치를 확인한다. 긴 로딩 중에도 작업 상태를 알 수 있고 취소 가능한 단계는 취소한다.
4. 사용자는 장면을 저장해 앱을 다시 열어도 같은 구성을 얻는다. 파일을 옮겼다면 누락 항목을 다시 연결하며, 해결 전 저장해도 원래 참조가 소실되지 않는다.
5. 사용자는 지정한 해상도와 시간의 PNG 또는 MP4를 내보낸다. 출력은 실시간 재생 속도와 무관한 고정 프레임 시간으로 계산되고 실패·취소 후 복구 가능하다.

## 3. 범위와 우선순위

P0은 해당 마일스톤의 출고 조건, P1은 후속 기능, P2는 조사 대상이다. 기능을 화면에 노출하기 전에 해당 기능의 Windows Player 검증을 통과해야 한다.

| 순서 | 묶음 | 포함 | 제외 또는 보류 |
|---|---|---|---|
| V0 | 전체 화면 뷰포트 | 창 전체 3D 렌더링, UI 오버레이의 개별·전체 숨김/복원, 입력 경계와 리사이즈 | 운영체제 전체 화면 강제 전환 |
| R0 | 1차 출시 준비 | 실입력 수동 QA, 실제 외부 배경, 누락 참조 보존, 클린 PC 실행, 배포 의존성·라이선스, 중급 PC 측정 | 새 그래픽 기능 |
| H1 | 제작 신뢰성 | 로딩 진행·취소, 재연결, Undo/Redo 기초, UI 코드 경계, 장면 스키마 이행 | 키프레임 편집·모션 블렌딩 |
| H2 | 장면 표현 | 툰·일반 재질 프리셋, DOF/SSAO, 후처리·조명 프리셋, 오디오와 카메라 VMD 연결 | MME `.fx` 범용 실행, 완전한 MMD 물리 호환 |
| H3 | 결과물 출력 | 지정 해상도 PNG, 고정 스텝 MP4, 오디오 동기, 취소·복구·품질 검사 | 실시간 화면 녹화, 플러그인 플랫폼 |

V0가 이번 고도화의 첫 구현 묶음이다. 기존 명세 4장의 고정 5영역 레이아웃과 충돌하는 부분은 V0의 전체 창 뷰포트·선택적 오버레이 정책을 우선한다. R0가 끝나면 1차 릴리스 후보 여부를 판단한다. H1~H3는 기존 명세의 2차 기능과 사용성 개선을 위한 후속 범위다. 버전 번호와 배포 날짜는 각 묶음의 검증 결과를 보고 정한다.

## 4. 기능 요구사항과 수용 기준

### V0 — 창 전체 뷰포트와 숨길 수 있는 UI (최우선)

**V0-01 뷰포트 영역 (P0).** Windows 앱 창의 클라이언트 영역 전체가 3D 장면의 렌더링·카메라 영역이다. 상단 도구 모음, 장면 탐색기, 속성 창, 재생 바, 탭·아이콘은 뷰포트 위에 겹치는 UI이며 3D 화면의 폭·높이를 영구적으로 차지하지 않는다. 창 크기를 바꾸거나 UI를 숨겨도 모델의 화면 좌표, 선택 광선, 기즈모 위치가 실제 표시와 일치해야 한다. 이 요구는 운영체제의 독점 전체 화면 모드를 뜻하지 않는다.

**V0-02 개별·전체 표시 전환 (P0).** 주요 조작 영역(상단 도구 모음, 장면 탐색기, 속성 창, 재생 바)과 화면에 겹치는 탭·아이콘을 각각 숨기고 다시 표시할 수 있다. 한 번에 조작 UI 전체를 숨기는 집중 보기 동작도 제공한다. 전체 숨김 뒤에는 장면을 가리는 고정 패널이 남지 않아야 하며, **항상 작동하는 복원 단축키**와 화면에서 찾을 수 있는 최소 복원 수단을 제공한다. 복원 수단의 모양·위치는 구현 설계에서 정하되 장면 감상을 방해하지 않게 한다. 표시 상태는 세션 중 유지하고, 재실행 시에는 조작 UI가 보이는 안전한 기본 상태로 시작한다. UI 표시 상태는 `.mmdscene`의 장면 데이터가 아니다.

**V0-03 입력과 예외 상태 (P0).** 보이는 패널 위 입력은 해당 UI에만 전달하고, 패널이 숨겨진 자리에서는 카메라 조작·객체 선택·기즈모 조작이 가능해야 한다. 텍스트 필드 포커스와 파일·삭제·미저장 확인 대화상자는 기존 입력 차단 정책을 유지한다. 오류·저장 확인·로딩 진행 같은 필수 메시지는 집중 보기에서도 표시되며 사용자가 닫거나 대응할 수 있어야 한다. 패널을 숨기는 중에 드래그가 진행되고 있었다면 드래그를 안전하게 종료하거나 취소한다.

**V0-04 수용 검사 (P0).** 실제 Windows Player에서 UI 전체 표시 → 개별 숨김/복원 → 전체 숨김 → 복원 → 창 리사이즈 순서로 확인한다. 1280×720과 1600×900, 배율 100%와 150%에서 모델·배경이 창 전체에 렌더링되고, 보이는 패널·숨겨진 자리·기즈모의 클릭 경계가 맞아야 한다. 모든 UI를 숨긴 상태에서도 카메라 회전·이동·줌과 복원 단축키가 동작해야 한다. 자동 검사와 실제 마우스·키보드 수동 확인 결과를 분리해 기록한다.

### R0 — 출시 준비

**R0-01 실제 입력과 레이아웃 (P0).** 실제 마우스·키보드로 orbit/pan/zoom, 메시 선택, W/E/R 기즈모, 텍스트 포커스 차단, 단축키, 삭제 확인을 검증한다. 1280×720과 1600×900, Windows 화면 배율 100%와 150%에서 패널과 3D 뷰포트가 맞아야 한다. 실패한 조작은 입력 장치·배율·재현 단계를 기록한다. 합성 입력 프로브만으로 완료 처리하지 않는다.

**R0-02 외부 파일과 장면 보존 (P0).** 자체 생성 fixture와 별개로 사용 허가가 확인된 실제 배경 PMX를 Player에서 가져오고 저장·재실행·재로드한다. PMX나 VMD가 없을 때 항목의 ID, 경로, 배치, 표시 상태와 모션 연결 정보를 문서 내 미해결 항목으로 보존한다. 사용자가 파일을 찾아 재연결하면 같은 항목을 복구한다. 미해결 상태에서 저장해도 참조가 조용히 삭제되지 않아야 한다. 잘못된 파일은 현재 정상 장면을 유지하며 오류를 보여준다.

**R0-03 배포 검증 (P0).** Release 후보 하나를 선정하고 Windows x64 클린 VM에서 설치 또는 압축 해제, 첫 실행, 외부 PMX/VMD 로드, 저장·재실행을 확인한다. 네이티브 DLL·VC++ 런타임의 배포 방식을 정하고 실제 포함물 및 고지 파일을 검사한다. 로그인·네트워크 없이 기본 로컬 작업이 가능해야 한다. Mono/IL2CPP 중 선정 근거와 미선정 백엔드의 상태를 기록한다.

**R0-04 성능·안정성 (P0).** 동일한 2캐릭터+배경+기본 효과 샘플을 1080p 중급 Windows PC에서 측정한다. 평균·1% low·최악 프레임 시간, 메모리, 모델/장면 로딩 시간을 남긴다. 기존 30 FPS 목표 충족 여부를 판단하며, 과거 1회 발생한 종료 접근 위반의 재발을 추적한다. 측정 장치와 설정을 보고서에 적는다.

### H1 — 제작 신뢰성

**H1-01 응답하는 파일 로딩 (P0).** 파일 검사·파싱·준비·Unity 객체 생성 단계를 구분해 상태와 실패 이유를 표시한다. 취소 가능한 단계에는 취소를 제공한다. 로드/교체 실패 또는 취소 시 기존 장면과 리소스 소유권이 유지되고 중복 객체가 남지 않아야 한다. Unity 객체 생성은 메인 스레드 제약을 따른다. 진행률을 계산할 수 없는 단계는 임의의 백분율 대신 단계명을 표시한다.

**H1-02 재연결과 저장 보호 (P0).** 누락 PMX/VMD를 탐색기와 Inspector에서 구별해 보여주고 새 경로로 재연결한다. 동일 장면 파일을 다른 위치로 옮긴 경우 상대 경로를 새 파일 기준으로 다시 계산한다. 미해결 참조를 삭제하려면 사용자가 해당 항목을 명시적으로 삭제해야 한다. 저장 전 스키마와 경로를 검증하고 임시 파일에 기록한 뒤 교체한다.

**H1-03 기본 Undo/Redo (P1).** 객체 추가·삭제, 배치/가시성, VMD 연결, 그래픽 설정의 사용자 확정 동작을 명령 단위로 되돌린다. 기즈모 한 번의 드래그는 한 명령으로 기록한다. 파일 로딩·내보내기·재생 시간 경과는 기록하지 않는다. Undo/Redo 뒤 선택, Inspector, dirty 상태와 저장 결과가 일치해야 한다. 메모리 또는 기록 개수 상한을 둔다.

**H1-04 UI·검증 구조 (P1).** 입력 라우팅, 선택 상태, 장면 명령, 화면 렌더링과 파일 대화상자를 분리한다. 기존 키·버튼 동작과 `.mmdscene` schema 1 파일을 보존한다. `PocBuild`의 반복 빌드가 추적 중인 `.unity` 파일을 무작위 fileID로 바꾸지 않게 한다. 통합 검증 명령 하나가 UI·복원·기본 회귀를 실행하고 결과 위치를 출력한다.

**H1-05 장면 형식 호환 (P0).** 새 저장 필드가 필요한 시점에 schema 2를 정의한다. schema 1 파일을 읽어 메모리에서 이행하고, 원본을 자동 덮어쓰지 않는다. 알 수 없는 상위 버전은 원본을 유지한 채 읽기 전용 오류로 거절한다. schema 1→2 이행, 누락 에셋, 다른 드라이브, 한글·공백 경로, 읽기 전용 폴더를 별도 검증한다.

### H2 — 장면 표현

**H2-01 재질 스타일 (P0, 기존 GFX-201/202).** 캐릭터용 툰 프리셋은 명암 경계·림 라이트·윤곽선의 사용 여부와 강도를 조절한다. 일반 배경용 재질은 호환 가능한 경우에만 PBR 모드를 제공한다. 원본 PMX 텍스처/재질을 영구 수정하지 않고 장면별 오버라이드로 저장한다. 미지원 재질은 폴백과 경고를 제공한다. 서로 다른 최소 2개 모델에서 피부·머리카락·투명 재질을 시각 비교한다.

**H2-02 효과와 조명 (P0, 기존 GFX-203~207).** DOF는 초점 대상 또는 거리와 블러 강도를, SSAO는 켜기·강도·반경을 제공한다. SSAO는 URP Renderer Feature의 런타임 제어 경로를 별도 검증한다. Vignette를 포함한 후처리·조명·품질 프리셋은 적용·초기화·장면 저장·복원할 수 있어야 한다. Motion Blur는 시각 품질과 성능 측정 후 포함 여부를 결정한다. 렌더 파이프라인 기본 Volume 프로파일과 앱 설정이 중복 적용되지 않아야 한다. 효과 OFF에서 기준 화면과 성능을 비교한다.

**H2-03 오디오 (H3 선행 P0, 기존 MMD-115).** 로컬 오디오를 공통 장면 시간에 연결하고 재생·정지·시킹·루프·속도 변경 동작을 정의한다. 지원 파일 형식은 Windows Player 디코딩 및 배포 조건 검사 후 확정하되 WAV를 최소 기준으로 삼는다. H3 영상 출력의 오디오 동기 검사를 시작하기 전에 이 요구를 통과해야 한다.

**H2-04 카메라 모션 (P1, 기존 MMD-116).** 카메라 VMD는 기존 단일 모델 경로의 제약을 명시한 채 공통 시계에 연결하고 수동 카메라와 우선순위/해제 동작을 제공한다. 미지원 VMD 카메라 채널은 경고하고 장면 전체를 손상시키지 않는다.

### H3 — 결과물 출력

**H3-01 PNG 캡처 (P0, 기존 GFX-208).** 사용자가 출력 경로와 해상도를 고른다. UI를 제외하고 현재 카메라·효과의 프레임을 출력한다. 장면 시간과 화면비 정책을 명시하고, 취소/파일 쓰기 실패 시 기존 파일을 손상시키지 않는다. 저장된 PNG의 실제 픽셀 크기·색·알파 정책을 검사한다.

**H3-02 MP4 오프라인 출력 (P0, 기존 GFX-209/210).** 시작/끝 시간, FPS(최소 30·60), 해상도, 출력 경로를 입력받는다. 시간 구간은 `[start, end)`이며 `frameIndex = 0 .. ceil((end-start) × FPS)-1`의 `t = start + frameIndex / FPS`에서 각 프레임을 평가한다. 예상 프레임 수를 출력 시작 전에 보여주고, 완료 후 실제 프레임 수·영상 길이·해상도·코덱을 검사한다. UI 재생 프레임률이나 창 크기가 결과에 영향을 주지 않아야 한다. 인코더는 배포 가능한 실행 방식·라이선스·오류 코드·로그·임시 파일 정리 정책을 구현 전에 확정한다.

**H3-03 오디오 동기와 실패 복구 (P0).** 오디오가 있는 장면은 출력 시작점과 길이에 맞춰 인코딩하고 0초·중간·끝의 동기 오차를 측정한다. 허용 오차는 한 출력 프레임 이내를 목표로 하되 측정 방법과 샘플레이트 변환 정책을 먼저 고정한다. 취소·디스크 부족·인코더 실패 후 손상된 최종 파일을 남기지 않고 임시 파일을 정리한다. 완료 전 최종 경로를 교체하지 않는다.

## 5. 데이터와 아키텍처 계약

- 장면 파일은 외부 에셋의 **참조**를 저장한다. PMX/VMD/오디오 원본을 `.mmdscene`이나 배포 패키지에 복사하지 않는다.
- 장면 객체의 안정적인 ID를 유지한다. 선택, Undo, 누락 항목 재연결과 저장 이행이 같은 ID를 사용한다.
- PMX 로더, 재생 시계, 렌더 설정, 장면 문서, 파일 출력은 분리된 서비스 경계를 가진다. UI 이벤트가 직접 파일 형식이나 네이티브 인코더 상태를 소유하지 않는다.
- 물리 OFF 장면의 재생·시킹·출력 결과를 기준으로 삼는다. 물리 토글은 상태 유지·대규모 시킹·실패 회복·연속 영상의 시각 검증을 통과한 뒤 별도 명세로 연다.
- 출력 작업은 원본 장면을 수정하지 않는 스냅샷 또는 명시적인 일시 정지 상태에서 수행한다. 완료·취소 뒤 사용자의 장면 시간, 선택과 설정을 복원한다.
- 외부 파일의 크기·형식·경로를 검사하고 오류 메시지에 사용자 경로와 조치 방법을 제공한다. 로그에는 버전·백엔드·실패 단계·예외를 남기되 모델 파일 내용은 기록하지 않는다.

## 6. 검증 및 완료 판정

각 티켓은 **Windows Player의 실제 외부 로딩**, 자동 검증, 필요한 사람의 시각/입력 확인을 구분해서 보고한다. 새 기능의 수용 결과에는 사용한 모델·모션과 사용 허가, 백엔드, Debug/Release, 해상도, OS, 보고서·스크린샷 경로를 적는다. 테스트 에셋은 계속 Git 밖에 둔다.

## 7. 명시적으로 뒤로 미루는 범위

모션 블렌딩, 키프레임·다중 트랙 편집, 자동 카메라, 플러그인 API, 범용 MME `.fx`, VRM/코이카츠 카드 직접 로딩, 네트워크/클라우드는 기존 3차 또는 별도 조사 범위다. material/UV 모프와 광범위한 PMX 호환성은 지원한다고 표시하지 않는다. 추가 호환 작업은 재현 가능한 모델과 기대 화면을 확보한 뒤 티켓화한다.

## 8. 구현 착수 전에 확정할 결정

1. V0의 조작 UI 기본 배치와 개별 숨김 버튼·전체 숨김/복원 단축키의 구체적인 위치와 키.
2. R0의 출시 후보 백엔드와 배포 형태(설치 프로그램 또는 압축 배포).
3. H1의 Undo 범위와 최대 기록 크기, 대형 PMX 로딩 중 실제 취소 가능 경계.
4. H2의 툰 룩 기준 이미지와 DOF/SSAO 품질·성능 허용선.
5. H3의 인코더 패키징/라이선스, 지원 오디오 형식, 기본 출력 FPS·해상도.

결정 전에도 R0 수동 QA와 누락 참조 보존 설계는 진행할 수 있다. 결정 결과는 `docs/DECISIONS.md`에 기록하고 이 문서의 버전을 올린다.
