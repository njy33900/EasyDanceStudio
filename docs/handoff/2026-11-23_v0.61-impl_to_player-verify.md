## 바꾼 것

### 1. 마우스 카메라 (명세 1절)

| 입력 | 동작 |
|---|---|
| 짧은 좌클릭(5 px 이내) | 선택·빈 곳이면 해제, 커서 아래 PMX 재질도 고름 |
| 좌드래그(5 px 초과) | 회전. 클릭 여유 안에서 참은 이동을 첫 회전에 반영. 놓아도 선택 안 바뀜 |
| 우드래그 | 거리: 위 = 가까이. `Distance × e^(−4·dy/뷰포트 높이)`. 가로 무시, 시야각 불변 |
| 휠버튼 / Shift+우드래그 | 이동(기존) |
| 휠 | 커서 아래 표면 쪽으로: 카메라가 그 점을 향한 직선 위로만 움직여 점이 화면 같은 자리에 남음. 회전 중심은 그 점의 깊이(시선축 위)로. 표면 없으면 회전 중심 쪽 |

- 파일: `ViewportInputRouter.cs`(규칙), `MmdViewportCamera.cs`(`Roll`, `Dolly`, `ZoomToward`, `Level`), `MmdSceneWorkspace.Input.cs`(`RaycastScene`이 점·PMX 재질까지 반환, `OnApplicationFocus`).
- 우선순위: 기즈모 손잡이 > 카메라. 카드·탭·대화상자 위에서 시작한 입력 무시, 시작된 드래그는 카드 위로 계속. 한 번에 한 버튼만. 버튼 해제·포커스 상실(`ViewportInputFrame.FocusLost`)·대화상자·Busy(로딩·출력)에서 종료; 포커스가 돌아와도 눌린 버튼으로 재개하지 않음.
- 카메라 VMD: 라우터가 **0이 아닌 양일 때만** Orbit/Pan/Dolly/Zoom을 부르므로, 누르기·선택 클릭·가로 우드래그로는 해제되지 않는다. 해제(`HandOverToManualView`)는 위치·방향·**roll**·**시야각**을 그대로 이어받는다. 시야각은 그래픽 설정 FOV가 된다(10~120° 제한, 실행 취소 기록 없음 = 뷰 상태).
- 그 때문에 **실행 취소가 명령이 바꾼 항목만 다시 적용**하도록 바꿨다(`MmdSceneWorkspace.Undo.cs` `ApplyLight(target, other)`). 예전에는 "현재와 다른 모든 항목"이었다. 기존 흐름에는 기록 밖 변경이 없어서 동작은 같아야 한다 — Player 검사로 확인할 것.
- 뷰 roll: 카메라 속성에 "화면 기울기 n° · 수평 맞추기"(기울었을 때만 표시), 뷰 초기화도 0으로. 저장: `view.roll`, `savedViews[].roll`(schema 2 선택 필드).
- 이전 `IViewportInputTarget.Zoom(float)`은 `Zoom(float, Vector2)`, `ProcessViewportInput`의 `orbitHeld` 인자는 `dollyHeld`(우버튼)로 바뀌었다.

### 2. 화면 보정 (명세 2절)

- 데이터 `MmdMaterialCorrection.cs`: `ColorCorrectionData`(대상 `tint` R/G/B 0~1, `brightness` 0~2, `materials[]`), `MaterialCorrectionData`(`index`, `name` = PMX 원래 이름, `tint`, `brightness`, `gloss` 0~1). 장면 파일 `sceneObjects[].correction`(schema 2 선택 필드).
- 적용 `MmdMaterialStyle.cs`(styler): 재질 슬롯마다 `MaterialPropertyBlock` — `_BaseColor`(현재 재질 색 × 대상 × 재질), 광택은 툰 `_Gloss` / PBR `_Smoothness`를 1 쪽으로. 원본 재질·PMX·텍스처는 건드리지 않음. 스타일이 바뀌면 다시 계산.
- 툰 셰이더 `_Gloss`(기본 0 → 기존 룩·기준 이미지 불변), `_GlossPower` = PMX 반사 강도(8~128, 없으면 32). 텍스처 속성은 추가하지 않았다(H2b-01의 D3D12 종료 크래시 원인 참고).
- 식별(`ResolveCorrections`): 번호+이름 일치가 먼저, 아니면 이름이 모델에 하나뿐일 때만(번호 이동으로 표시). 이름 없음·중복·다른 항목과 충돌은 **적용 안 함 + 보관 + 이유 표시**. 열기·다시 찾기 때 맞지 않는 항목이 있으면 불러오기 문제 목록에 한 줄.
- UI `MmdSceneWorkspace.Correction.cs`: 속성 "화면 보정" 절(상태, 보정 전 보기, 대상 색·밝기 초기화, 대상 R/G/B·밝기), 접힌 "재질별 보정"(재질 목록 = 그려지는 PMX 재질, 지원 여부·적용 상태, R/G/B·밝기·광택, 이 재질 보정 초기화, 식별 실패 목록). 뷰포트 클릭으로 재질 선택. 보정 전 보기 중엔 뷰포트 위에 "보정 전 화면" 표시(`StudioTheme.uss` `.eds-compare-chip`).
- 비교: `MmdSceneService.ShowCorrections(bool)` — 데이터는 그대로, 블록만 끔. 저장 안 됨. 값을 바꾸거나 출력하면 자동으로 다시 켬(출력은 항상 보정 적용).
- 실행 취소: `ObjectState.correction`(JSON). 슬라이더 끌기는 "재질 보정: <이름>" / "대상 색·밝기"로 묶임.

## 성능 (명세 3절 "재생 중 카메라 조작이 밀리지 않는지", 커밋 후 추가 측정)

`PocScenePerformanceProbe.cs`에 재생 중 매 프레임 카메라 입력 패스 3개(좌드래그 회전, 우드래그 거리, 휠 표면 쪽)와 전 객체 화면 보정 패스·렌더 비용을 추가했다. `bash scripts/bash/run-scene-perf.sh release IL2CPP`(1920×1080 창 약 3~4분). 결과는 `docs/TASKS.md` v0.61 항목: 입력·보정 모두 재생 프레임 시간에 차이 없음, 휠 입력 처리 중앙값 0.57 ms·최악 2.94 ms. 첫 측정에서 본 룩 프리셋 렌더 비용 저녁 실외 +97%는 측정 잡음이었다: 렌더 비용을 3회 재고(첫 회 버림) 낮은 값을 쓰게 바꾸니 +2%(툰 캐릭터 포함 +6%), 기능별 분해도 모두 ±0.02 ms. 한계 +50% 이내.
