## 1. 목적과 현재 기준선

목표는 외부 PMX/VMD를 불러와 재생하는 현재 앱을 **장면을 안전하게 만들고, 꾸미고, 결과물을 내보낼 수 있는 데스크톱 도구**로 발전시키는 것이다. 첫 화면 목표는 **앱 창 전체를 3D 뷰포트로 쓰고 조작 UI를 필요할 때만 보이게 하는 것**이다. 기존 1·2·3차 구분을 대체하지 않으며, 1차 출시 준비 사항과 2차 기능 전에 필요한 품질 작업을 함께 규정한다.

현재 구현: 다중 캐릭터와 정적 PMX 배경, 공통 재생 시계, 선택·W/E/R 기즈모, 카메라/방향광/기본 후처리, `.mmdscene` schema 1 저장·복원, 밝은 미니멀 UI. Debug/Release × Mono/IL2CPP에서 UI 95개와 별도 프로세스 복원 9개가 통과했고, Codex가 `v0.6`의 Debug/Mono PowerShell 전체 빌드 및 95+9 검사, 씬 26·복구 13·변형 21·물리 lifecycle 20 검사를 다시 통과시켰다. 이 수치는 **자동 검사 범위의 결과**이며 실제 마우스 조작, 다양한 외부 파일, 다른 PC의 품질 보증은 아니다.

**알려진 결함 (R0-02a에서 수정됨):** 장면을 열 때 PMX가 없거나 로드에 실패한 항목이 장면에서 제외되어, 저장하면 해당 항목의 경로·배치·모션 연결이 파일에서 사라졌다. 모션 파일만 없는 캐릭터도 모션 경로를 잃었다. 2026-11-19 수정·검증 완료.

**제품 포지셔닝 (0.5):** MikuMikuDance 본체는 2019년 9.32 이후 갱신이 멈췄고 MME도 2014년 0.37이 마지막이다. Blender + mmd_tools는 품질이 높지만 학습 곡선과 렌더 시간이 크고, Unity·웹 라이브러리는 개발자용이다(`docs/RESEARCH_COMPETITIVE_EDGE.md`). EasyDanceStudio는 **"MMD 자산을 그대로 쓰면서, 설정 없이 바로 보기 좋은 영상을 뽑고, 작업을 잃지 않는 앱"**을 목표로 한다. 강점은 (1) MMD만큼 되면서 더 쉽다 — 물리·오디오·MP4·룩 프리셋, (2) MMD에 없는 것 — 자동 카메라·립싱크·모션 맞춤 보정 순서로 쌓는다.

유지할 제약: 일반 화면 물리 OFF(ADR-014 — **0.5에서 PH 묶음으로 개정 제안, 확정 전까지 유지**), 테스트 에셋은 `Assets/`·Git·배포물 밖, 로컬 모델/Ollama 사용 금지, 드래그 앤 드롭은 1차 범위 제외(ADR-015). 영상 출력은 Unity Editor 전용 Recorder에 의존하지 않는 Windows Player 기능이어야 한다.

## 2. 사용자 작업 흐름

1. 사용자는 앱 창 전체에 펼쳐진 장면을 보면서 조작 패널·탭·아이콘을 숨기거나 다시 연다. UI를 모두 숨겨도 뷰포트를 조작하고 UI를 복원할 수 있다.
2. 사용자는 PMX 캐릭터 2개 이상과 PMX 배경을 추가하고 각 캐릭터에 VMD를 연결한다.
3. 사용자는 물리를 켜서 머리카락·옷의 움직임을 확인하고(PH), 룩 프리셋 하나로 조명·효과·재질을 정한 뒤 세부를 조절하며(H2a-05), 음악에 맞춘 자동 카메라를 만들어 손볼 수 있다(D-01). 카메라, 조명, 재질 스타일과 효과를 조절하고 재생 위치를 확인한다. 긴 로딩 중에도 진행 단계를 알 수 있고 취소 가능한 단계는 취소한다.
4. 사용자는 장면을 저장해 앱을 다시 열어도 같은 구성을 얻는다. 파일을 옮겼다면 누락 항목을 다시 연결하며, **해결 전에 저장해도 원래 참조는 사라지지 않는다.** 앱이 비정상 종료돼도 최근 작업을 복구할 수 있다.
5. 사용자는 지정한 해상도와 시간의 PNG 또는 MP4를 내보낸다. 숏폼용 세로 화면과 합성용 투명 배경 PNG 시퀀스도 프리셋으로 고른다(H3-04). 물리를 켠 장면은 굽기 캐시로 미리보기와 같은 결과를 낸다. 출력은 실시간 재생 속도와 무관한 고정 프레임 시간으로 계산되고 실패·취소 후 복구 가능하다.

## 4. 기능 요구사항과 수용 기준

### R0-02a — 누락 참조 보존 (최우선, P0)

장면을 열 때 PMX가 없거나 로드에 실패한 항목, VMD가 없거나 실패한 모션 연결을 **문서 안의 미해결 항목으로 보존**한다. 미해결 항목은 ID, 종류, 원래 저장 경로 문자열, 배치, 표시 상태, 모션 경로를 그대로 유지하고, 탐색기에 미해결 상태로 표시하며 3D 객체·재생 시간에는 기여하지 않는다. 저장하면 미해결 항목이 원래 값 그대로 다시 기록된다. 같은 폴더에 저장하면 경로 문자열을 그대로 쓰고, 다른 폴더에 저장하면 같은 파일을 가리키도록 상대 경로만 다시 계산한다. 다시 열어도 항목 ID는 유지된다. 사용자가 명시적으로 삭제한 경우에만 문서에서 제거한다. 모션만 없는 캐릭터는 캐릭터를 불러오되 모션 경로를 미해결로 유지한다.

수용: 누락 배경·누락 모션이 있는 파일을 열고 → 다른 항목을 수정 → 저장 → 다시 열었을 때, 미해결 항목의 모든 필드가 원본과 같다. 자동 검사(실제 Player)와 이전 동작 대비 회귀 검사를 함께 남긴다.

### V0 — 창 전체 뷰포트와 숨길 수 있는 UI

**V0-01 뷰포트 영역 (P0).** 앱 창 클라이언트 영역 전체가 3D 장면의 렌더링·카메라 영역이다. 상단 도구 모음, 장면 탐색기, 속성 창, 재생 바, 탭·아이콘은 뷰포트 위에 떠 있는 UI이며 3D 화면의 폭·높이를 영구적으로 차지하지 않는다. 창 크기를 바꾸거나 UI를 숨겨도 모델의 화면 좌표, 선택 광선, 기즈모 위치가 실제 표시와 일치해야 한다. 운영체제의 독점 전체 화면 모드를 뜻하지 않는다.

**V0-02 개별·전체 표시 전환 (P0).** 주요 조작 영역(상단 도구 모음, 장면 탐색기, 속성 창, 재생 바)과 뷰포트 위 탭·아이콘(기즈모 모드 바 등)을 각각 숨기고 다시 표시할 수 있다. 조작 UI 전체를 한 번에 숨기는 **집중 보기**를 제공한다. 전체 숨김 뒤에는 장면을 가리는 고정 패널이 남지 않아야 하며, **항상 작동하는 복원 단축키**와 화면에서 찾을 수 있는 최소 복원 수단(예: 모서리의 작은 반투명 버튼)을 제공한다. 표시 상태는 세션 중 유지하고, 재실행 시에는 조작 UI가 보이는 안전한 기본 상태로 시작한다. UI 표시 상태는 `.mmdscene` 장면 데이터가 아니다.

**V0-03 입력과 예외 상태 (P0).** 보이는 패널 위 입력은 해당 UI에만 전달하고, 패널이 숨겨진 자리에서는 카메라 조작·객체 선택·기즈모 조작이 가능해야 한다. 텍스트 필드 포커스와 파일·삭제·미저장 확인 대화상자는 기존 입력 차단 정책을 유지한다. 오류·저장 확인·로딩 진행 같은 필수 메시지는 집중 보기에서도 표시되며 대응할 수 있어야 한다. 패널을 숨기는 중에 드래그가 진행 중이면 안전하게 종료한다.

**V0-04 수용 검사 (P0).** 실제 Windows Player에서 UI 전체 표시 → 개별 숨김/복원 → 전체 숨김 → 복원 → 창 리사이즈 순서로 확인한다. 1280×720과 1600×900, 배율 100%와 150%에서 모델·배경이 창 전체에 렌더링되고, 보이는 패널·숨겨진 자리·기즈모의 클릭 경계가 맞아야 한다. 모든 UI를 숨긴 상태에서도 카메라 회전·이동·줌과 복원 단축키가 동작해야 한다. 자동 검사와 실제 마우스·키보드 수동 확인 결과를 분리해 기록한다.

**V0-05 프레이밍 안전 영역 (P0).** "전체 보기", "선택 보기"(F), 장면 열기·객체 추가 후 자동 프레이밍은 **현재 보이는 패널이 덮지 않는 영역**에 대상이 들어오도록 계산한다(카메라 렌즈 시프트 또는 동등한 방법). 패널을 숨기거나 다시 표시해도 이미 맞춘 시점이 갑자기 튀지 않아야 한다. 수용: 패널 표시/집중 보기 각각에서 프레이밍 후 대상 경계가 안전 영역 안에 투영되는지 검사한다.

**V0-06 화면 배율(DPI) 정책 (P0).** 현재 UI는 1280×720 기준 화면 크기 비례 확대만 한다. Windows 배율 150%에서 글자·버튼 크기, 클릭 판정, 카메라 영역이 맞는지 측정하고, 필요하면 화면 크기와 DPI를 함께 고려하는 배율 규칙을 정한다. 결정 내용과 측정 스크린샷을 남긴다.

### R0 — 출시 준비

**R0-01 실제 입력과 레이아웃 (P0, V0 이후).** V0가 적용된 최종 레이아웃에서 실제 마우스·키보드로 orbit/pan/zoom, 메시 선택, W/E/R 기즈모, 텍스트 포커스 차단, 단축키, 삭제 확인, 집중 보기·복원을 검증한다. 1280×720과 1600×900, 배율 100%와 150%에서 확인한다. 실패한 조작은 입력 장치·배율·재현 단계를 기록한다. 합성 입력 프로브만으로 완료 처리하지 않는다. 사용 허가가 확인된 **실제 배경 PMX 하나 이상**을 Player에서 가져오고 저장·재실행·재로드한다.

**R0-03 배포 검증 (P0).** Release 후보 하나를 선정하고 Windows x64 클린 VM에서 압축 해제(또는 설치), 첫 실행, 외부 PMX/VMD 로드, 저장·재실행을 확인한다. `UMTNativePlugin.dll`이 요구하는 VC++ 2015–2022 런타임(`VCRUNTIME140.dll`, `VCRUNTIME140_1.dll`, UCRT)의 배포 방식을 정하고 실제 포함물과 고지 파일을 검사한다. 로그인·네트워크 없이 기본 로컬 작업이 가능해야 한다. Mono/IL2CPP 중 선정 근거와 미선정 백엔드의 상태를 기록한다.

**R0-04 성능·안정성 (P0).** `scripts/Invoke-ScenePerformance.ps1`의 동일 샘플(2캐릭터 + 전체 길이 VMD + 배경 + 기본 효과)을 1080p **중급 Windows PC**에서 Release로 측정한다. 평균·1% low·최악 프레임 시간, 메모리, 모델/장면 로딩 시간을 남기고 30 FPS 목표 충족 여부를 판단한다. 과거 1회 발생한 종료 접근 위반의 재발을 계속 추적한다. 측정 장치와 설정을 보고서에 적는다.

### H1 — 제작 신뢰성

**H1-00 로딩 분리 조사 (P0, H1-01 선행).** UMT `PMXImporter.Import`/VMD 변환 경로에서 파일 검사·파싱을 백그라운드 스레드로 분리할 수 있는지, Unity 객체 생성을 여러 프레임에 나눌 수 있는지, 실제 취소 가능한 경계가 어디인지 고정 커밋의 코드로 확인한다. 결과(가능/불가능 단계, 필요한 어댑터, 패키지 수정 없이 가능한지)를 문서로 남긴 뒤 H1-01 범위를 확정한다.

**H1-01 응답하는 파일 로딩 (P0).** H1-00 결과에 따라 파일 검사·파싱·준비·Unity 객체 생성 단계를 구분해 상태와 실패 이유를 표시한다. 취소 가능한 단계에만 취소를 제공한다. 로드/교체 실패 또는 취소 시 기존 장면과 리소스 소유권이 유지되고 중복 객체가 남지 않아야 한다. Unity 객체 생성은 메인 스레드 제약을 따른다. 진행률을 계산할 수 없는 단계는 임의의 백분율 대신 단계명을 표시한다.

**H1-02 재연결과 저장 보호 (P0).** R0-02a로 보존된 미해결 PMX/VMD를 탐색기와 Inspector에서 구별해 보여주고 새 경로로 재연결한다. 재연결 시 같은 항목 ID와 배치·모션 정보를 복구한다. 장면 파일을 다른 위치에 저장하면 해결된 참조의 상대 경로를 새 파일 기준으로 다시 계산한다. 미해결 참조를 없애려면 사용자가 항목을 명시적으로 삭제해야 한다. 저장 전 스키마와 경로를 검증하고 임시 파일에 기록한 뒤 교체한다.

**H1-03 기본 Undo/Redo (P1).** 객체 추가·삭제, 배치/가시성, VMD 연결, 그래픽 설정의 사용자 확정 동작을 명령 단위로 되돌린다. 기즈모 한 번의 드래그와 숫자 필드 한 번의 확정은 각각 한 명령이다. 파일 로딩 자체·내보내기·재생 시간 경과는 기록하지 않는다(추가된 객체의 삭제/복원은 기록). Undo/Redo 뒤 선택, Inspector, dirty 상태와 저장 결과가 일치해야 한다. 기록 상한(제안 200개)을 둔다.

**H1-04 UI·렌더·검증 구조 (P1).** 입력 라우팅, 선택 상태, 장면 명령, 화면 렌더링, 파일 대화상자를 분리한다(명세 4.11의 `ViewportInputRouter`, `SelectionService` 등). 기존 키·버튼 동작과 `.mmdscene` schema 1 파일을 보존한다. `PocBuild`의 반복 빌드가 추적 중인 `.unity` 파일을 무작위 fileID로 바꾸지 않게 한다. 통합 검증 명령 하나가 UI·복원·기본 회귀를 실행하고 결과 위치를 출력한다. UI 문자열을 리소스로 분리한다.

**H1-05 장면 형식 호환 (P0).** 새 저장 필드(미해결 항목 상태, 재질 오버라이드, 오디오 등)가 필요한 시점에 schema 2를 정의한다. schema 1 파일을 읽어 메모리에서 이행하고 원본을 자동 덮어쓰지 않는다. 알 수 없는 상위 버전은 원본을 유지한 채 오류로 거절한다. schema 1→2 이행, 누락 에셋, 다른 드라이브, 한글·공백·특수문자 경로, 읽기 전용 폴더, 네트워크 경로를 별도 검증한다.

**H1-06 자동 저장과 비정상 종료 복구 (P0).** 미저장 변경이 있을 때 일정 간격(제안 2분)으로 원본과 별도의 복구 파일을 원자적으로 기록한다. 정상 저장·종료 시 복구 파일을 정리한다. 다음 실행 때 복구 파일이 남아 있으면 복구/버리기를 묻는다. 복구 파일은 원본 `.mmdscene`을 덮어쓰지 않는다. 수용: 저장 안 된 변경 후 프로세스를 강제 종료하고 재실행해 복구 결과가 같은지 확인한다.

**H1-07 최근 파일 (P1, 기존 MMD-114).** 최근 연 장면 목록(제안 10개)을 앱 설정에 저장하고 열기 메뉴에서 제공한다. 없는 파일은 목록에서 구별 표시하고 제거할 수 있다. 장면 파일 내용은 저장하지 않는다.

**H1-08 진단 정보 (P1, NFR-07).** 로그 파일 위치를 앱에서 열 수 있고, 버전·백엔드·OS·GPU·최근 오류를 모은 진단 정보를 사용자가 확인한 뒤 파일로 내보낼 수 있다. 모델 파일 내용이나 사용자 경로 외의 개인 정보는 넣지 않는다.

### PH — 물리 (0.5 신규, ADR-017)

기존 자산: `MmdStatefulPhysicsSolver`/`MmdPhysicsPlayback`(POC-06G, 60 Hz 정수 틱, 시킹 = 0초 리셋 후 예열), 전체 길이 2회 재현성(POC-06D, 0.001 m 이내), 기능 대조(POC-06F). 일반 UI 연결, 다중 캐릭터, 시각 품질은 아직 검증되지 않았다(`docs/PHYSICS_*.md`).

**PH-00 연결 조사 (P0, 선행).** 다중 캐릭터 공통 시계(`MmdSceneService`)와 상태형 물리 서비스의 시간 소유권을 정한다. 물리는 재생 중 고정 60 Hz 틱으로 진행하고 화면 프레임률과 무관해야 한다. 캐릭터별 물리 상태 분리, 장면 교체(H1-01c 트랜잭션)·모델 삭제 때 Native 자원 해제, IL2CPP 동작, 2캐릭터 + 배경의 프레임 시간 비용을 측정해 문서로 남긴다. 결과로 PH-01~04 범위와 성능 목표를 확정한다.

**PH-01 선택형 물리 재생 (P0).** 장면 전체 및 캐릭터별 물리 ON/OFF를 제공하고 장면 파일에 저장한다(schema 2, H1-05). 상태 표시줄은 현재 물리 상태를 표시한다. **튐 검사:** 한 틱(1/60초)에 0.3 m 넘게 움직이는 물리 본이 반복되면 불안정으로 표시한다(PH-00에서 Gene 망토 추 강체가 1,199틱 중 558틱 해당). 물리 계산이 실패(비유한 값, 예외, 시간 초과)하면 **해당 캐릭터만 물리 OFF로 되돌리고 경고**하며 장면은 계속 재생한다. 물리를 끄면 기존 OFF 결과와 같은 포즈가 나와야 한다.

**물리 대상 범위:** PMX에 정의된 **모든 강체·조인트를 MMD와 같은 기준으로 계산**한다. 머리카락·치마·옷자락·액세서리뿐 아니라 **가슴·엉덩이 등 신체 2차 움직임 부위**도 빠짐없이 포함한다. 이 부위들은 대부분의 MMD 캐릭터 모델에 표준으로 리깅되어 있고, 빠지면 MMD 대비 움직임이 굳어 보여 핵심 경쟁력을 잃는다. 특정 부위를 임의로 제외하거나 약하게 처리하지 않으며, 조절은 사용자 설정(PH-04)으로만 한다.

**PH-02 시킹·예열·리셋 (P0).** 캐시된 구간은 캐시로 즉시 이동한다(PH-03). 캐시 밖에서는 앞으로 짧게 이동하면 틱을 진행하고, 뒤로 또는 크게 이동하면 리셋 후 예열한다. 물리 상태 체크포인트(Bullet 상태 저장·복원)의 가능성을 UMT 패치 후보로 조사한다. 예열이 길면 진행 표시와 취소를 제공하고, 취소하면 이전 시간과 상태로 돌아간다. 재생 시작 전 **예열 구간**(제안 1초)으로 첫 프레임 튐을 줄인다. 같은 시간으로 두 번 시킹하면 같은 포즈가 나와야 한다(백엔드 내 재현성).

**PH-03 물리 굽기 캐시 (P0, H3 선행 — PH-00 결과로 재생의 기본 경로).** PH-00 측정에서 강체 571개 모델의 한 틱이 평균 11 ms, 30초 시킹이 20초였으므로 실시간 계산만으로는 재생·시킹이 불가능하다(`docs/PH00_PHYSICS_INTEGRATION.md`). 물리를 켜면 백그라운드(프레임 분할)로 전체 구간을 계산해 진행 표시·취소와 함께 캐시하고, 캐시가 계산된 구간까지만 물리 포즈로 재생·시킹한다. 지정 구간의 물리 결과를 고정 틱으로 계산해 메모리(필요 시 임시 파일)에 저장하고, 재생·시킹·출력이 캐시를 우선 사용한다. 모델·모션·물리 설정·시작 시간이 바뀌면 캐시를 무효화한다. 출력(H3)은 캐시가 없으면 먼저 굽고, 캐시와 출력의 포즈가 같아야 한다. 캐시 크기 상한과 메모리 사용을 보고한다.

**PH-04 부위별 조절과 관통 완화 (P1).** 원본 PMX를 바꾸지 않고 장면별로 조절하는 최소 설정: 물리 강도(중력·감쇠 배율), 예열 길이, 캐릭터별 충돌 여유(가능한 경우). **부위별 강도**(머리카락, 치마·옷, 가슴, 엉덩이, 액세서리, 기타)를 제공한다. 부위 분류는 강체·본 이름(일본어 표준 이름과 흔한 변형)과 연결 본으로 자동 추정하고, 분류하지 못한 강체는 "기타"로 두며 사용자가 고칠 수 있다. 기본값은 모든 부위 1.0배(모델 원래 설정 그대로)다. 하위 스텝 수(1/120초 ↔ 1/60초) 선택으로 실시간 비용을 줄이는 옵션을 품질 비교 후 제공한다. 두 모델에서 머리카락·치마의 관통 전후 이미지를 남긴다. 가슴·엉덩이 강체가 있는 모델로 부위 분류 결과, 1.0배에서 MMD 기준 움직임과의 비교, 과도한 떨림·튐이 없는지(빠른 안무 구간 포함)를 검증한다. 강체 편집기와 천 시뮬레이션은 범위 밖이다.

**PH-05 신체 흔들림 — 스프링 본 (P1, ADR-018).** 가슴·엉덩이 **본은 있지만 강체가 없는** 모델에 2차 움직임을 일괄로 더한다. 업계 표준(코이카츠 DynamicBone, VRM SpringBone, 블렌더 Wiggle, 언리얼 Kawaii Physics)과 같은 **스프링 본** 방식이다(`docs/RESEARCH_SECONDARY_MOTION.md`). Bullet 강체를 추가하지 않는다.
- 진단: 모델마다 가슴·엉덩이 후보 본(이름 + 정점 가중치), 그 본에 강체가 있는지, 적용 가능 여부를 인스펙터에 보여준다. 강체가 이미 있는 본은 기존 물리를 쓰고 스프링을 붙이지 않는다.
- 계산: 우리 소유의 감쇠 스프링(verlet) 솔버. 물리 OFF 포즈를 따라 본 끝점이 관성·탄성으로 늦게 따라오도록 본을 회전시킨다. 60 Hz 틱으로 **미리 굽고**(물리 굽기 캐시와 같은 방식), 재생·시킹·출력은 캐시를 쓴다. 결정적이어야 한다(같은 입력 → 같은 결과).
- 조절: 프리셋 약·중·강(강성·감쇠·중력 영향·최대 각도), 기존 부위별 강도(가슴·엉덩이) 슬라이더와 함께 동작한다. 설정은 장면 파일에 캐릭터별로 저장한다. 원본 PMX는 바꾸지 않는다.
- 일괄 적용: "모든 캐릭터에 신체 흔들림 적용" 버튼. 적용 화면에 모델 이용 규약 확인 안내. 기본 OFF.
- 수용: 진단 결과가 실제 본 구조와 일치, 결정성(두 번 구운 결과 동일), 튐 검사 0, 전후 화면, 틱당 비용, 장면 저장·재열기.

수용: 2캐릭터 + 전체 길이 VMD에서 물리 ON 재생·뒤로 시킹·장면 교체·삭제를 반복해도 Native 자원과 객체 수가 늘지 않고(H1-01 반복 검사 방식), 굽기 캐시 기반 출력이 미리보기와 같은 포즈를 낸다. 성능 목표는 PH-00 측정 후 확정한다(제안: 개발 PC Release 물리 ON 60 FPS, 중급 PC 30 FPS).

### H2a — 효과·조명 (기존 GFX-203~207)

**H2a-01 기본 Volume 정리 (P0, 선행).** 현재는 카메라 후처리를 켜면 URP 템플릿의 기본 프로파일(Vignette, Film Grain, Split Toning 등)이 섞이므로 런타임에 모든 Volume 컴포넌트를 중립값으로 덮어쓰고 있다. 이를 **프로젝트의 파이프라인/전역 기본 Volume 프로파일을 앱 기준(중립)으로 정리**하는 방식으로 바꾸고, 런타임 덮어쓰기는 앱 설정만 담당하게 한다. 셰이더 variant stripping이 앱이 쓰는 효과를 제거하지 않는지 Player에서 렌더 결과로 확인한다.

**H2a-02 DOF·SSAO·후처리 (P0).** DOF는 초점 대상 또는 거리와 블러 강도를, SSAO는 켜기·강도·반경을 제공한다. SSAO는 `PC_Renderer`에 Renderer Feature를 추가하고 런타임 활성/파라미터 제어 경로를 별도 검증한다. Vignette를 포함한 후처리·조명·품질 프리셋은 적용·초기화·장면 저장·복원할 수 있어야 한다. Motion Blur는 시각 품질과 성능 측정 후 포함 여부를 결정한다. 효과 OFF 기준 화면과 성능을 비교한다.

**H2a-03 오디오 (P0, H3 선행, 기존 MMD-115).** 로컬 오디오를 공통 장면 시간에 연결하고 재생·정지·시킹·루프를 정의한다. 시킹 정확도는 샘플 단위(`timeSamples`) 기준으로 정의한다. **재생 속도 0.5~2배에서의 정책**을 정한다: 제안 기본값은 1배가 아닐 때 음높이를 함께 바꿔 재생하고 그 사실을 표시하는 것(Unity에 피치 유지 시간 늘이기가 기본 제공되지 않음). 지원 형식은 Windows Player 디코딩 및 배포 조건 검사 후 확정하되 WAV를 최소 기준으로 한다.

**H2a-04 카메라 모션 (P1, 기존 MMD-116).** 카메라 VMD를 기존 단일 모델 경로의 제약을 명시한 채 공통 시계에 연결하고, 수동 카메라와의 우선순위·해제 동작을 제공한다. 미지원 카메라 채널은 경고하고 장면 전체를 손상시키지 않는다.

**H2a-05 룩 프리셋 (P0, 0.5 신규).** 조명(방향·색·세기), 후처리(블룸·DOF·SSAO·색보정), 재질 스타일(H2b 이후 연결)을 한 번에 적용하는 **묶음 프리셋**을 제공한다. 기본 제공 프리셋은 최소 3개(예: 밝은 무대, 저녁 실외, 어두운 클럽 — 기준 이미지는 사용자와 확정). 프리셋을 적용한 뒤 개별 값을 바꾸면 "수정됨"으로 표시하고, 사용자 프리셋으로 저장·삭제할 수 있다. 장면 파일에는 프리셋 이름과 실제 값을 함께 저장해, 프리셋이 나중에 바뀌어도 장면 결과가 유지된다. 수용: 각 프리셋의 기준 화면과 성능(결정 9의 허용선), 적용·초기화·저장·재실행 복원.

### H2b — 재질 스타일 (기존 GFX-201/202, 별도 마일스톤)

**H2b-01 재질 스타일 (P0).** 캐릭터용 툰 프리셋은 명암 경계·림 라이트·윤곽선의 사용 여부와 강도를 조절한다. 일반 배경용 재질은 호환 가능한 경우에만 PBR 모드를 제공한다. 원본 PMX 텍스처/재질을 영구 수정하지 않고 장면별 오버라이드로 저장한다. 미지원 재질은 폴백과 경고를 제공한다. 구현 전 확인 사항: UMT MMD 셰이더와의 관계(대체/병행), SDEF·스키닝 경로와의 호환, 투명 재질 정렬, 커스텀 셰이더의 Player 포함(Always Included 또는 참조 자산)과 variant 수. 서로 다른 최소 2개 모델에서 피부·머리카락·투명 재질을 전후 비교한다.

### H3 — 결과물 출력

**H3-01 PNG 캡처 (P0, 기존 GFX-208).** 사용자가 출력 경로와 해상도를 고른다. UI를 제외하고 현재 카메라·효과의 프레임을 출력한다. 장면 시간과 화면비 정책을 명시하고, 취소/파일 쓰기 실패 시 기존 파일을 손상시키지 않는다. 저장된 PNG의 실제 픽셀 크기·색·알파 정책을 검사한다.

**H3-02 MP4 오프라인 출력 (P0, 기존 GFX-209/210).** 시작/끝 시간, FPS(30·60, **기본 60**), 해상도(기본 1920×1080), 출력 경로를 입력받는다. 60 FPS는 30 FPS 대비 렌더 프레임 수와 출력 시간이 두 배이므로 예상 프레임 수와 함께 예상 소요를 표시한다. 시간 구간은 `[start, end)`이다. **프레임 수와 프레임 시간은 부동소수 누적·`ceil` 오차가 없도록 정수 또는 유리수로 계산한다**: 시작·끝을 정수 틱(예: 1/600000초 또는 오디오 샘플)으로 고정하고 `frameCount = ceilDiv((endTicks - startTicks) × FPS, ticksPerSecond)`, `t(i) = start + i / FPS`를 유리수로 평가한 뒤 재생 시계에 전달한다. 예상 프레임 수를 출력 시작 전에 보여주고, 완료 후 실제 프레임 수·영상 길이·해상도·코덱을 검사한다. UI 재생 프레임률이나 창 크기가 결과에 영향을 주지 않아야 한다.

**인코더:** 1순위 후보는 **Windows Media Foundation H.264 인코더**(OS 제공, 별도 코덱 배포·특허 라이선스 부담이 적음)를 네이티브 플러그인으로 호출하는 방식이다. Media Feature Pack이 없는 Windows N 에디션에서는 사용할 수 없으므로 감지·안내한다. 대안은 외부 FFmpeg 프로세스이며, 이 경우 빌드 구성(LGPL/GPL)·H.264 코덱 특허·재배포 고지를 구현 전에 확정한다. 어떤 방식이든 오류 코드·로그·임시 파일 정리 정책을 먼저 정한다.

**H3-03 오디오 동기와 실패 복구 (P0).** 오디오가 있는 장면은 출력 시작점과 길이에 맞춰 인코딩하고 0초·중간·끝의 동기 오차를 측정한다. 허용 오차는 한 출력 프레임 이내를 목표로 하되 측정 방법과 샘플레이트 변환 정책을 먼저 고정한다. 취소·디스크 부족·인코더 실패 후 손상된 최종 파일을 남기지 않고 임시 파일을 정리한다. 완료 전 최종 경로를 교체하지 않는다.

**H3-04 숏폼·합성 출력 (P1, 0.5 신규).** 출력 프리셋: 세로 1080×1920(9:16) 30/60 FPS, 정사각 1080×1080, 가로 1920×1080. 세로 출력이면 뷰포트에 출력 영역 안내선을 보여주고 V0-05 프레이밍 안전 영역과 함께 동작한다. **투명 배경 PNG 시퀀스**(배경·바닥·하늘 제외, 알파 포함)를 제공하고, 반투명 재질·후처리와 알파의 관계(프리멀티플라이 여부)를 명시한다. 수용: 각 프리셋의 실제 크기·프레임 수·알파 채널 검사.

### D — 차별화 (0.5 신규, P1~P2)

MMD 본체에 없거나 외부 도구가 필요한 기능이다. 모든 분석은 **로컬에서** 수행하고 네트워크·클라우드·외부 AI 서비스에 사용자 파일을 보내지 않는다(8.2절 결정 16). 생성 결과는 항상 **사용자가 수정할 수 있는 일반 데이터**(카메라 트랙, 모프 키)로 저장한다.

**D-01 박자 기반 자동 카메라 (P1, H2a-03·H2a-04 선행).** 장면 오디오에서 템포(BPM)·박자·구간 에너지를 신호 처리로 추정하고, 카메라 템플릿(정면 고정, 전신↔상반신 컷, 느린 궤도, 클로즈업)을 박자 경계에 배치해 **편집 가능한 카메라 트랙**을 생성한다. 대상 캐릭터·컷 빈도·흔들림 정도·시드를 입력받고, 같은 입력과 시드면 같은 결과가 나와야 한다. 생성된 트랙은 장면에 저장하고, 가능한 범위에서 카메라 VMD로 내보낸다. 수용: BPM이 알려진 테스트 음원 2개 이상에서 박자 추정 오차, 박자 경계에 맞는 컷의 비율, 캐릭터가 화면 밖으로 나가지 않는지 검사.

**D-02 오디오 립싱크 (P2 조사 → P1).** 보컬 오디오에서 모음(あ·い·う·え·お)과 입 닫힘 구간을 추정해 표준 입 모프 키를 생성한다. 조사 단계에서 (a) 음량·포먼트 기반 신호 처리, (b) 가사 텍스트 + 타이밍 보조, (c) 그 외 방식을 비교하고 정확도·처리 시간·배포 조건을 문서로 남긴다. 표준 입 모프가 없는 모델은 경고한다. 기존 VMD에 입 모프가 있으면 덮어쓰지 않고 사용자가 고르게 한다. 반주가 섞인 음원에서의 한계를 명시한다.

**D-03 모션 맞춤 보정 (P1).** 모션과 모델이 맞지 않을 때의 진단과 보정. (1) **진단**: 누락 본·모프 목록(현재 `MmdMotionSummary.missingBones/missingMorphs`), 준표준 본(グルーブ, 腰, 上半身2, 足IK親, 捩り 본 등) 누락과 예상 증상을 사용자 언어로 보여준다. (2) **런타임 보완**: PMX 파일을 바꾸지 않고 메모리에서 준표준 본을 보완하는 방식의 가능성을 조사·구현한다. (3) **접지 보정(조사)**: 체형 차이로 생기는 발 미끄러짐·바닥 관통을 줄이는 선택형 보정. 수용: 준표준 본이 없는 모델과 있는 모델에서 같은 VMD의 전후 비교 이미지와 수치(발 위치 오차).

**D-04 VRM 지원 조사 (P2).** VRoid 등 VRM 모델 사용자층을 위한 가져오기 가능성(라이선스 메타 표시 포함), VMD 적용 시 본 매핑, 재질(MToon) 처리, 배포 조건을 조사해 별도 티켓 여부를 정한다.

## 5. 데이터와 아키텍처 계약

- 장면 파일은 외부 에셋의 **참조**를 저장한다. PMX/VMD/오디오 원본을 `.mmdscene`이나 배포 패키지에 복사하지 않는다.
- 장면 객체의 안정적인 ID를 유지한다. 선택, Undo, 미해결 항목 보존·재연결, 저장 이행이 같은 ID를 사용한다.
- **불러오지 못한 항목도 문서의 일부다.** 런타임 객체가 없다는 이유로 문서 항목을 버리지 않는다(R0-02a).
- PMX 로더, 재생 시계, 렌더 설정, 장면 문서, 파일 출력은 분리된 서비스 경계를 가진다. UI 이벤트가 직접 파일 형식이나 네이티브 인코더 상태를 소유하지 않는다.
- 물리 OFF 장면의 재생·시킹·출력 결과를 기준으로 삼는다. 물리 ON(PH)은 **고정 60 Hz 틱**으로 진행하고 화면 프레임률과 무관하며, 출력은 굽기 캐시를 거쳐 미리보기와 같은 결과를 낸다. 물리 실패는 캐릭터 단위 OFF 폴백으로 격리한다. PH 게이트(6절)를 통과하기 전에는 기존 OFF 정책을 유지한다.
- 자동 생성 기능(D)은 결과를 일반 장면 데이터로 저장하고, 생성기 버전·입력·시드를 함께 기록해 다시 생성할 수 있게 한다. 사용자 파일을 앱 밖으로 보내지 않는다.
- 출력 작업은 원본 장면을 수정하지 않는 스냅샷 또는 명시적인 일시 정지 상태에서 수행한다. 완료·취소 뒤 사용자의 장면 시간, 선택과 설정을 복원한다.
- 시간은 표시용 초(double)와 별개로, 출력·오디오 동기 경로에서 정수 틱 또는 샘플 단위를 기준으로 한다.
- 외부 파일의 크기·형식·경로를 검사하고 오류 메시지에 사용자 경로와 조치 방법을 제공한다. 로그에는 버전·백엔드·실패 단계·예외를 남기되 모델 파일 내용은 기록하지 않는다.

## 7. 명시적으로 뒤로 미루는 범위

모션 블렌딩, 키프레임·다중 트랙 편집, 플러그인 API, 범용 MME `.fx`, 코이카츠 카드 직접 로딩, 네트워크/클라우드, 영상·웹캠 모션 캡처 자체 구현(외부 도구가 만든 VMD/BVH 가져오기는 별도 검토), 천 시뮬레이션·강체 편집기는 기존 3차 또는 별도 조사 범위다. 자동 카메라는 D-01, VRM은 D-04 조사로 옮겼다(0.5). material/UV 모프와 광범위한 PMX 호환성은 지원한다고 표시하지 않는다. 추가 호환 작업은 재현 가능한 모델과 기대 화면을 확보한 뒤 티켓화한다. 드래그 앤 드롭은 ADR-015에 따라 제외를 유지한다.
