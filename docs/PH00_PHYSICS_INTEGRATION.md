# PH-00 — 물리 연결 조사 (2026-11-20, Claude · 측정 완료)

명세: `ENHANCEMENT_SPEC_v0.5.md` PH-00, 결정 ADR-017. 1~3절은 코드 확인, 4~6절은 Release IL2CPP 실제 Player 측정 결과와 결론이다.

## 1. 이미 있는 것 (코드 확인)

| 구성 | 위치 | 내용 |
|---|---|---|
| 상태형 솔버 | `Assets/MMDStudio/UMTExtensions/MmdStatefulPhysicsSolver.cs` (UMT.Runtime asmref) | 모델별 `MMDTransformManager`의 컨텍스트로 한 스텝: 비물리 본 입력 갱신 → IK 토글 동기 → `TransformBonesWithPhysics`(물리 전 처리 → Bullet → 물리 후 처리) → 본·강체 Transform 반영. Native 컨텍스트를 직접 만들지 않음(모델 소유) |
| 재생 세션 | `Poc/MmdPhysicsPlayback.cs` | 정수 60 Hz 틱, `Advance`(남는 시간 보존, 프레임당 최대 240스텝), 루프, `Seek` = 0초 리셋 후 목표 틱까지 재계산(비용이 목표 시간에 비례) |
| 소유권 | `MmdPocMotion.AcquirePhysics/AcquireSceneClock` | 물리 세션과 장면 시계는 **서로 배타적**. 지금은 장면에 들어간 모션은 물리를 가질 수 없다 |
| 검증 이력 | `docs/PHYSICS_*.md` | 전체 길이(184.7초) 2회 재현성 0.001 m 이내, 공식 변환과 동일 포즈(POC-06F), 수명 검사 20개. 단일 모델·진단 경로만 |

**강체 범위:** 솔버는 `Kinetic`이 아닌 모든 강체(`Dynamic`, `DynamicBoneAligned`)의 본을 물리 본으로 취급한다. 강체를 이름·부위로 거르지 않으므로 **가슴·엉덩이·머리카락·치마 등 PMX에 정의된 강체 전부가 이미 같은 방식으로 계산 대상**이다(ADR-017 요구와 일치). `DynamicBoneAligned`(물리+본 위치 맞춤, 가슴 강체에 흔함)는 UMT `MMDRigidBody`가 따로 처리한다 — 실제 모델로 동작 확인 필요(측정 M3).

## 2. 연결 설계 (제안)

1. **시계:** `MmdSceneService`가 장면 시계를 계속 소유하고, 물리를 켠 캐릭터마다 `MmdPhysicsPlayback`과 같은 정수 60 Hz 틱 진행기를 **장면 서비스 안에서** 돌린다. 모션 소유권을 "장면 시계 + 물리"로 합친 새 모드가 필요하다(`AcquireSceneClock`와 `AcquirePhysics`의 배타 조건 변경).
2. **틱 진행:** 화면 프레임마다 경과 시간을 60 Hz 틱으로 나눠 진행(현재 `Advance`와 같음). 렌더 프레임률과 무관.
3. **시킹:** 지금은 0초부터 다시 계산하므로 3분 곡 끝으로 이동하면 약 10,800스텝. 비용(M2)에 따라 (a) 체크포인트 캐시(PH-03 굽기 캐시와 공유), (b) 긴 예열의 비동기화·취소를 정한다.
4. **장면 교체·삭제:** 물리 세션은 모델의 Native 물리 컨텍스트를 쓰므로 모델 해제 전에 세션을 먼저 `Dispose`해야 한다. H1-01c 트랜잭션(`CommitScene`의 `Clear`)과 삭제 경로에 넣는다.
5. **실패 폴백:** 스텝 뒤 본 위치가 비유한 값이거나 큰 범위를 벗어나면(내구 검사의 100 m 기준) 그 캐릭터 세션을 닫고 물리 OFF 샘플로 돌아간다.

## 3. MMD 기준과 다를 수 있는 점 (확인 필요)

- **모델 간 충돌:** UMT는 모델마다 `MMDPhysicsManager`(별도 Bullet 월드)를 둔다. MMD에서는 여러 모델의 강체가 한 물리 세계에 있어 서로 부딪힐 수 있는 것으로 안다 **[지식, 검증 필요]**. 두 캐릭터가 가까이 춤출 때 차이가 날 수 있다(M5).
- **바닥:** UMT는 바닥 충돌 그룹(15)을 둔다. 배경 PMX 강체와 캐릭터 강체의 상호작용 여부 확인(M5).
- **물리 스텝:** UMT 내부는 1/120초 하위 스텝을 쓴다(`PLAYER_PHYSICS_VALIDATION.md`). MMD 설정(기본 프레임 대비 스텝 수)과의 차이를 기록.

## 5. 결론 — PH 범위 조정

1. **굽기 캐시(PH-03)를 재생의 기본 경로로.** 실시간 계산은 미리보기 보조로 두고, 물리를 켜면 백그라운드(프레임 분할)로 전체 구간을 계산해 포즈를 캐시한다. 진행 표시·취소, 캐시가 앞서가는 구간까지만 물리 재생. 모델·모션·설정이 바뀌면 다시 굽는다. Sandrone급 3분 곡은 약 2분이 걸린다(개발 PC).
2. **시킹은 캐시 우선.** 캐시가 없는 구간으로의 시킹은 "물리 준비 중"으로 표시하고 물리 OFF 포즈를 보여준 뒤 캐시가 따라오면 바꾼다. 물리 상태 저장·복원(체크포인트)은 UMT의 Bullet 상태 직렬화 가능성을 조사(패치 후보 #2).
3. **캐시 크기:** 물리 본만, 위치+회전, 60 Hz 저장 시 Sandrone 약 500본 × 11,000틱 × 28 B ≈ 150 MB. 30 Hz 저장+보간 또는 압축을 PH-03에서 결정.
4. **실시간 비용 옵션(PH-04):** 하위 스텝 수(UMT 내부 1/120초 → 1/60초) 선택, 캐릭터별 물리 끄기. 품질 차이는 측정 후.
5. **불안정 강체(Gene 망토 추):** PH-01 수용 조건에 "튐 검사"(0.3 m/틱 초과 횟수)를 넣고, 원인(추 강체 질량·조인트 설정·UMT 처리)을 화면 확인과 함께 조사한다. MMD에서 같은 모델이 어떻게 보이는지 비교가 필요.
6. **캐릭터 간 충돌:** MMD와 다를 가능성이 높다 **[지식, 검증 필요]**. 공유 물리 세계는 UMT 패치가 필요해 P2로 둔다.
7. **가슴·엉덩이:** 강체가 있으면 다른 부위와 똑같이 계산되고 안정적이다(Sandrone 가슴 6개). 엉덩이 강체가 있는 모델로 추가 확인 필요(이번 두 모델에는 없음).

## 6. PH-03 굽기 캐시 엔진 (2026-11-20, Claude · Release IL2CPP 검증)

**구현:**
- `Poc/MmdPhysicsBake.cs`: 캐릭터 하나의 상태형 60 Hz 물리를 프레임당 시간 예산(기본 8 ms, 최소 1틱)만큼 미리 계산한다. 물리 영향 본(비고정 강체의 본 + 물리 후 처리 본)의 로컬 위치·회전을 틱마다 저장한다. `Apply(t)`는 일반 물리 OFF 포즈 위에 캐시된 본을 덮어쓴다(틱 사이는 보간). 계산되지 않은 시간에는 `false`를 돌려주고 포즈를 바꾸지 않는다.
- 장면의 일반 포즈 샘플(`SolveTransforms`)은 물리 솔버와 같은 상태 배열을 덮어쓴다. 그래서 굽기 스텝마다 `MmdStatefulPhysicsSolver.SaveState/RestoreState`로 상태를 보존한다. **확인(2026-11-20, 10절):** 복원하지 않으면 굽기 조각 경계마다 다음 한 틱이 틀어진다. 복원은 필수다. 물리 영향 본 목록은 `PhysicsAffectedBones()`로 얻는다.
- `MmdPocMotion.SampleBakeStep`: 장면 시계가 모션을 소유한 채로 굽기 스텝을 실행한다. 화면 포즈는 장면이 매 조각 뒤에 다시 샘플한다.

**검증** `PocPhysicsBakeProbe`(`-pocPhysicsBakeReport`), `bash scripts/bash/run-physics-bake.sh <cfg> <backend>`: 끊김 없는 기준 시뮬레이션의 체크포인트 포즈를 (물리 OFF 샘플 + 캐시 적용) 결과와 전 본 월드 위치로 비교한다. 굽기는 조각마다 화면을 다른 시간으로 다시 샘플하며 진행한다.

| 모델 | 검사 구간 | 최대 오차 | 상태 복원 없이(음성 대조) | 캐시 본 | 곡 전체 캐시 | 굽기 속도 | 곡 전체 굽기 | 굽는 중 최악 프레임 |
|---|---|---|---|---|---|---|---|---|
| Gene_light | 20초 + 전체 | **5.4 μm** | 4.36 m (조각 경계 한 틱 오류, 10절) | 100 | 29.6 MB | 1,417틱/초 | **7.8초**(실측) | 15.7 ms |
| Sandrone | 10초 | **0.7 μm** | 0 m | 533 | **157.7 MB** | 60틱/초 | **약 185초**(추정) | 31.1 ms |

틱 사이 보간 적용과 계산 범위 밖 거부도 확인했다.

**남은 과제:**
1. **굽기 시간:** Sandrone급은 한 틱(11~28 ms)이 프레임 예산보다 커서 프레임당 1틱으로 3분이 걸린다. 일시정지 중 예산 확대(UI 30 FPS 허용), 하위 스텝 옵션(PH-04), 워커 스레드 계산(Transform 의존 제거 필요, 큰 작업)을 비교한다.
2. **캐시 크기:** Sandrone 158 MB. 회전 압축(16 → 8 B)과 위치가 변하지 않는 본의 위치 생략으로 크게 줄일 수 있다. 다음 단계.
3. **장면 연결:** 캐릭터별 물리 토글, 장면 샘플에서 `Apply`, 굽기 진행 표시·취소, 모델·모션 교체와 삭제 시 무효화, 장면 저장. Sandrone의 음성 대조 오차 0은 이 모델이 샘플 덮어쓰기 영향을 받지 않는 구조이기 때문으로 보인다. 그래도 복원은 모든 모델에 적용한다.

## 7. 장면 연결 (2026-11-20, Claude · Release IL2CPP 검증, 실험 기능)

ADR-017은 "PH 게이트 통과 전까지 UI는 물리 OFF"였다. 사용자 요청으로 **캐릭터별 "물리 (실험)" 토글(기본 OFF)**로 먼저 연결했다. 게이트(튐 검사·성능·시각 확인)는 아직이다.

- `MmdSceneService`: `SetPhysics(id, on)`. 켜면 `MmdPhysicsBake`를 만들어 매 프레임 한 캐릭터씩 예산 8 ms로 굽는다(라운드로빈). 굽기 조각 뒤 그 캐릭터의 포즈를 다시 표시한다. `Seek`은 물리 OFF 샘플 뒤에 캐시를 덮어쓴다(계산 안 된 시간은 OFF 포즈). 모션 교체 시 다시 굽고, 배치(위치·회전·크기)가 바뀌면 처음부터 다시 굽는다(물리가 월드 공간·바닥 기준이라). 굽기 실패 시 그 캐릭터만 물리를 끄고 이유를 표시한다. 삭제·장면 비우기 시 캐시를 버린다.
- 인스펙터 모션 섹션: "물리 (실험)" 토글과 상태 문구("물리 준비 중 n% · 준비된 구간까지 물리로 재생", "물리 준비 완료", 끈 이유). 배경과 VMD 없는 캐릭터는 비활성.
- 장면 파일: `SceneObjectData.physics`(선택 필드, 기본 false). schema 1 그대로 — 예전 버전은 이 필드를 무시해 물리 OFF로 연다. 열 때 켜진 캐릭터는 처음부터 다시 굽는다(캐시는 저장하지 않음).

**검증:** UI 프로브 **130/130**(+4), 복원 9/9 — Release IL2CPP·Release Mono.
- `physics_toggle_only_for_characters_with_motion`: 배경은 비활성, 캐릭터에서 켜면 그 캐릭터만 ON, 변경 표시.
- `physics_bake_completes_changes_pose_and_repeats`: 3초 테스트 모션 굽기 13프레임, 준비 완료 문구, 2초 포즈가 OFF 대비 최대 0.79 m 다름, 다른 시간을 거쳐 다시 와도 동일 포즈.
- `physics_rebakes_after_placement_change`: 배치를 바꾸면 준비 상태가 풀리고 다시 완료.
- `physics_flag_saved_reopened_and_turned_off`: 캐릭터별 플래그 저장, 다시 열면 그 캐릭터만 ON, 끄기.

**주의:** 0.79 m 차이는 Gene 망토 추(錘) 강체의 불안정(4절 M3)일 가능성이 높다. 실험 기능을 기본으로 바꾸기 전에 화면 확인과 튐 검사가 필요하다. 남은 것: 캐시 압축, 굽기 속도(Sandrone급 약 3분), 굽는 동안 프레임 시간 측정(UI 경로), 재생 중 계산되지 않은 구간 처리(지금은 OFF 포즈).

## 9. 물리 마무리 1차 (2026-11-20, Claude · Release IL2CPP)

**캐시 압축:** 회전은 int16×4(8 B), 위치는 쉬는 위치(rest)로부터의 float16 오프셋(6 B)으로 저장한다. 굽기가 끝나면 한 번도 움직이지 않은 본의 위치 트랙을 버린다.

**튐 검사:** 메시 정점 가중치가 있는 본만 대상으로, 한 틱에 0.3 m 넘게 움직인 틱 수·처음 시간·최대 이동을 기록한다. 인스펙터에 "물리가 불안정한 구간" 경고를 띄운다.

**일시정지 가속:** 재생 중 굽기 예산 8 ms, 일시정지 중 24 ms(UI 약 30 FPS).

| 모델 | 오차(기준 대비) | 곡 전체 캐시 | 위치 트랙 | 가중치 있는 물리 본 | 튐 | 곡 전체 굽기 |
|---|---|---|---|---|---|---|
| Gene_light | 0.36 mm | **29.6 → 9.0 MB** | 100 중 9 | 52 | **0틱**(최대 6 cm, 아호게) | 7.9초(8 ms 예산) |
| Sandrone | 0.10 mm | **158 → 70.7 MB** | 533 중 405 | 439 | **0틱**(최대 14 cm, 옆머리) | **131.6초**(24 ms 예산, 실측) — 굽는 동안 평균 31 FPS, 최악 61 ms |

- 오차 허용치를 0.1 mm에서 2 mm로 바꿨다(양자화 때문). 실측 0.1~0.36 mm.
- Gene의 9 m 튐(망토 추)은 가중치 없는 본이라 검사에서 빠진다. 화면 확인(8절)과 일치한다.
- 음성 대조(상태 복원 없이)가 실행마다 달랐던 이유는 10절에서 밝혔다. 체크포인트 7개만 보았기 때문이다.

**부위별 강도(PH-04):** 강체·본 이름으로 물리 본을 머리카락·옷·치마·가슴·엉덩이·장신구·기타로 나눈다(`MmdPhysicsParts`, 강체가 없는 본은 가장 가까운 분류된 조상을 따른다). 재생할 때 물리 OFF 포즈와 구운 포즈를 부위별 비율(0~100%)로 섞는다. **다시 굽지 않고 즉시** 반영된다. 인스펙터는 모델에 있는 부위만 슬라이더로 보여준다. 장면 파일에 `physicsParts`/`physicsStrength`(선택 필드)로 저장한다. 100%를 넘는 강조(더 출렁이게)는 섞기로 표현할 수 없어 범위 밖이다. 하려면 UMT 강체 파라미터를 바꾸고 다시 구워야 한다.

**검증:** UI 프로브 **131/131**(+1 `physics_part_strength_blends_without_rebake`: 모든 부위 0%면 물리 OFF 포즈와 차이 0 m, 100%로 되돌리면 구운 포즈와 완전히 같음), 복원 9/9 — Release IL2CPP. `Invoke-SceneVerification.ps1` UI 기준 131.

## 10. 음성 대조 변화 조사 (2026-11-20, Claude · Release IL2CPP)

**질문:** PH-03 첫 실행에서 Gene의 "상태 복원 없이" 굽기는 기준과 4.36 m 달랐다. 이후 실행에서는 0.4 mm였다. 상태 복원은 필요한가?

**경과:**
1. 체크포인트 7개 비교, 변형 6개(복원 유무·반복·화면 갱신 끼워넣기 유무·튐 검사의 월드 위치 읽기 유무): 모두 같은 오차. 4.36 m를 냈던 커밋을 다시 빌드해 2회 실행해도 0 m. 이 단계에서 "일회성 결과, 복원은 방어용"이라고 잘못 결론지었다.
2. 같은 검사를 다시 돌리자 "복원 없음 반복"의 **t1199 한 틱만** 2.01 m이고 바로 다음 t1200은 0.2 mm였다. 혼돈적 발산이라면 회복되지 않는다. 그래서 **한 틱짜리 오류**로 보았다.
3. **모든 틱(1,201개)을 기준과 비교**하도록 프로브를 바꿨다.

**결과 (Gene, 1 cm 넘게 틀린 틱):**

| 변형 | 틀린 틱 | 최대 |
|---|---|---|
| 상태 복원 있음 | **0 / 1201** | 2.6 mm(양자화) |
| 복원 없음 / 다시 | **91 / 1201**, 91 / 1201 | 8.3 m, 8.8 m (`frontkuroku2_2tsumu`) |
| 복원 없음 + 화면 갱신 끼워넣기 없음 | 0 / 1201 | 2.6 mm |
| 복원 없음 + 월드 위치 읽기 없음 | 90 / 1201 | 7.3 m |
| 복원 있음 + 월드 위치 읽기 없음 | 0 / 1201 | 2.6 mm |

Sandrone은 모든 변형에서 0 / 601(0.1 mm).

**결론:**
- 상태를 복원하지 않으면 **굽기 조각 사이에 화면을 다시 샘플할 때마다 바로 다음 한 틱이 틀어진다.** 틀린 틱 수(91)가 조각 경계 수(1,200틱 ÷ 조각당 약 13틱 ≈ 92)와 같다. 그다음 틱은 Bullet의 실제 상태로 회복된다. 원인은 화면 샘플(`SolveTransforms`)이 덮어쓴 솔버 상태 배열이다. 튐 검사의 월드 위치 읽기는 무관하다.
- 영향받는 본은 이 상태에 의존하는 본이다(Gene 망토 추). Sandrone에는 그런 본이 없다. 가중치 있는 본이 그런 구조라면 한 프레임 깜박임으로 보이게 된다.
- **상태 복원은 필수**이며 PH-03 첫 설명(6절)이 맞았다. 첫 실행의 4.36 m와 2.01 m가 가끔만 보였던 이유는 체크포인트 7개 중 하나가 우연히 조각 경계 바로 뒤에 걸렸을 때만 드러났기 때문이다(조각 경계는 프레임 시간에 따라 바뀐다).
- 프로브는 이제 모든 틱을 비교하고 허용치는 5 mm다(압축 양자화 최대 2.6 mm). 복원 없는 대조군이 실제로 틀어지는지도 함께 보고한다.
- 실험 중 만든 "솔버 상태 변화 직접 측정"은 초기화되지 않은 필드(0 쿼터니언·NaN) 때문에 저장 직후 비교에서도 항상 "변화"로 나와 무효였다. 지웠다.
